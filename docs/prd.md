## 1. 목표 및 배경

### 목표
- 하루 안에 개발할 수 있는 "감성적인" 할 일 목록 웹 애플리케이션을 제공한다.
- 단순한 작업 관리를 넘어, 사용자에게 정서적 위안과 심리적 안정감을 준다.
- 사용자가 작업을 완료할 때마다 "작은 위로"를 받는 경험을 선사한다.
- 사용자가 성취감을 느끼고, 긴 업무 시간 동안 조금이나마 더 편안함을 느끼도록 돕는다.

### 배경
이 프로젝트는 많은 직장인들이 업무 시간 동안 느끼는 외로움과 정서적 지지의 필요성에서 출발했습니다. 우리는 할 일 목록이라는 일상적인 도구를, 매일의 작은 성공을 축하하고 위로를 주는 감성적인 경험으로 전환하고자 합니다. 사용자가 작업을 완료할 때마다 디지털 바질 화분이 자라나고 격려의 메시지가 나타나는 핵심 기능을 통해, 반복적인 업무에 긍정적인 감성을 불어넣고 사용자의 심리적 안정감에 기여하는 것을 목표로 합니다.

## 2. 요구사항

### 기능 요구사항 (Functional Requirements)
- **FR1:** 사용자는 할 일을 텍스트로 추가할 수 있다.
- **FR2:** 사용자는 추가된 할 일 목록을 볼 수 있다.
- **FR3:** 사용자는 할 일을 '완료'로 표시할 수 있다.
- **FR4:** 할 일을 완료하면, 화면에 긍정적인 시각적 효과가 재생된다.
- **FR5:** 할 일을 완료하면, 화면에 격려의 메시지가 무작위로 표시된다.
- **FR6:** 할 일을 완료할 때마다, 화면의 바질 화분이 조금씩 자란다.
- **FR7:** 바질 화분의 성장 상태는 앱을 다시 시작해도 유지된다.

### 비기능 요구사항 (Non-Functional Requirements)
- **NFR1:** 웹 애플리케이션은 하루 안에 개발이 완료되어야 한다.
- **NFR2:** 백엔드는 Spring/Java 17을 사용해야 한다.
- **NFR3:** 프론트엔드는 React를 사용해야 한다.
- **NFR4:** 인프라 비용은 거의 또는 전혀 발생하지 않아야 한다.
- **NFR5:** 사용자 인터페이스는 단순하고 직관적이어야 한다.

## 3. 사용자 인터페이스(UI) 디자인 목표

- **전반적인 UX 비전:** 따뜻하고, 미니멀하며, 위로를 주는 경험. 사용자가 웹사이트를 열 때마다 작은 정원을 가꾸는 듯한 평온함을 느끼게 한다.
- **핵심 상호작용 방식:** 직관적인 제스처 기반의 상호작용. 불필요한 클릭이나 복잡한 메뉴는 최소화한다.
- **핵심 화면 및 뷰:** 단일 화면 애플리케이션(Single Page Application)으로, 모든 기능(할 일 목록, 바질 화분)이 한 화면에 집중된다.
- **접근성:** WCAG AA
- **브랜딩:** 전체적으로 부드러운 파스텔 톤 또는 흙(earth-tone) 색상을 사용한다. 폰트는 손글씨체나 부드러운 느낌의 세리프체를 사용하여 아날로그 감성을 더한다.
- **대상 디바이스 및 플랫폼:** Web Responsive (웹 반응형)

## 4. 기술적 가정

- **리포지토리 구조:** Monorepo (모노레포)
- **서비스 아키텍처:** Monolith (모놀리식)
- **테스팅 요구사항:** Unit Only (단위 테스트만 진행)
- **추가 기술 가정:**
    - 애플리케이션은 Spring Boot 백엔드가 제공하는 단일 페이지 애플리케이션(SPA)으로 설계된다.
    - 데이터 영속성을 위해, `docker-compose.yml`에 명시된 대로 **MySQL 8.0 데이터베이스**를 사용한다. (`application.yml`에 해당 접속 정보가 설정되어 있음)
    - 배포는 백엔드와 프론트엔드 자산을 모두 포함하는 단일 실행 가능 JAR 파일로 진행한다. 이 애플리케이션은 Docker Compose를 통해 실행되는 MySQL 데이터베이스에 연결된다.

## 6. 에픽 1: 상세 내용
**목표:** 풀스택(Spring/React) 프로젝트 구조를 설정하고, 기본적인 할 일 관리(CRUD) 기능을 구현하며, 사용자가 작업을 완료할 때마다 바질 화분이 성장하고 격려 메시지가 나타나는 핵심적인 '위로의 순환' 경험을 제공한다.

### 스토리 1.1: 프로젝트 구조 설정 및 상태 확인
- **As a** 개발자,
- **I want** Spring Boot와 React를 모노레포 안에 설정하고, 데이터베이스 연결을 확인하며, 기본 상태 확인(health check) 엔드포인트를 만들어서,
- **so that** 본격적인 기능 개발을 시작할 수 있는 안정적인 기반을 마련할 수 있다.

**완료 조건:**
1. Spring Boot와 React 프로젝트가 모노레포 구조 안에 생성된다.
2. 백엔드 애플리케이션이 시작될 때 MySQL 데이터베이스에 성공적으로 연결된다.
3. `/api/health` 엔드포인트에 GET 요청을 보내면 200 OK 응답을 받는다.
4. React 애플리케이션을 시작하면, 임시 환영 페이지가 화면에 표시된다.

### 스토리 1.2: 할 일(To-Do) 관리 API 구현
- **As a** 개발자,
- **I want** 할 일을 생성(Create), 조회(Read), 수정(Update)할 수 있는 백엔드 API를 만들어서,
- **so that** 프론트엔드에서 할 일 데이터를 관리할 수 있다.

**완료 조건:**
1. `POST /api/todos`: 요청 본문(request body)의 내용으로 새로운 할 일을 데이터베이스에 생성한다.
2. `GET /api/todos`: 데이터베이스에 있는 모든 할 일 목록을 조회한다.
3. `PUT /api/todos/{id}`: 특정 ID의 할 일 상태를 '완료'로 변경한다.

### 스토리 1.3: 기본 할 일 UI 구현
- **As a** 사용자,
- **I want** 할 일 목록을 보고, 새로운 할 일을 추가하고, 기존 할 일을 완료 처리할 수 있어서,
- **so that** 기본적인 할 일 관리 기능을 사용할 수 있다.

**완료 조건:**
1. 웹 애플리케이션이 로드될 때, 백엔드에서 할 일 목록을 가져와 화면에 표시한다.
2. 입력창에 텍스트를 입력하고 버튼을 클릭하여 새로운 할 일을 추가할 수 있다.
3. 새로운 할 일을 추가하면, 페이지 새로고침 없이 목록에 즉시 나타난다.
4. 목록에 있는 할 일의 체크박스나 버튼을 클릭하여 '완료' 상태로 변경할 수 있다.

### 스토리 1.4: '위로의 순환' 핵심 기능 구현
- **As a** 사용자,
- **I want** 할 일을 완료할 때마다 바질 화분이 자라고, 격려 메시지와 시각 효과가 나타나서,
- **so that** 작은 성취감을 느끼고 정서적인 위로를 받을 수 있다.

**완료 조건:**
1. 화면에 바질 화분 이미지가 항상 표시된다.
2. 할 일을 완료하면, 바질 화분 이미지가 약간 더 성장한 이미지로 변경된다.
3. 현재 화분의 성장 단계는 데이터베이스에 저장되어, 웹 애플리케이션을 다시 시작해도 유지된다.
4. 할 일을 완료하면, 미리 정의된 목록에서 무작위로 선택된 격려 메시지가 잠시 동안 화면에 표시된다.
5. 할 일을 완료하면, 반짝이는 효과와 같은 단순하고 기분 좋은 시각 효과가 나타난다.
